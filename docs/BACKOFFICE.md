# 後台：流程規劃

第 184 項，店主 2026-11-16：「接著建置後台，流程給你規劃好。」

## 後台是什麼

遊戲只存在它自己的分頁裡：重新整理就從頭開始，不存進度（`App.tsx` 載入時會清掉每日帳與評價，只有 3D 畫面掉了的那一次會接著玩）。所以後台不是讀存檔的工具，而是**連著正在跑的那一局的主控台**，跟線上遊戲的伺服器管理後台一樣：
- 遊戲分頁是「伺服器」，每秒把現況告訴後台。
- 後台看得到這一局的營運狀況，也能下幾個指令。

## 怎麼用

1. 打開後台：dev 是 http://localhost:5173/admin.html，網站是 `/GrilledFishBusiness/admin.html`。店面編輯器的「視窗 → 後台」也能開。
2. 在**同一個瀏覽器**打開遊戲（後台右上角的「開遊戲」）。後台自動連上，左上角變成「已連線」。
3. 左邊選要看的頁面：

| 頁面 | 內容 |
|---|---|
| 總覽 | 現金（比資本少時是紅的）、累計營收、累計支出、評價、來客、店內客人與待出的單、營業中與否、遊戲時間與速度；最新八則日誌 |
| 帳本 | 資本、營收、收銀機取款、各項支出（進貨、炭火、薪資、加班、水電、開業、供品、宣傳），最後是現金 |
| 每日結算 | 每天打烊的結算表：營收、盈虧、來客、評價、賣最好的菜 |
| 評價 | 總評價與料理、服務、環境三項；每則評價的星數、評語、等了多久、扣分的原因 |
| 客人與點單 | 店裡每位客人的狀態（等餐、用餐中…）、座位、點了幾道；還沒出的單 |
| 員工 | 請了誰、什麼職位、現在上班還是休息 |
| 日誌 | 這一局的日誌，跟遊戲左下角的一樣 |
| 遊戲控制 | 遊戲速度（一倍、兩倍）；跳到某個時間（早上、開店前、開店、深夜、打烊前，或自己指定），給測試用 |

## 怎麼做的

- 頁面：`admin.html`，Vite 的第三個頁面。程式在 `src/ui/admin/`：`AdminApp.tsx` 是介面，`admin.css` 是樣式，文字在 `src/data/adminText.ts`（中日英）。
- 很輕：不載 3D、不載遊戲的樣式，打包後 JS 18 KB、CSS 5 KB。
- 連線：`src/ui/admin/link.ts`，用瀏覽器的 BroadcastChannel，只有同一個網站、同一個瀏覽器的分頁之間收得到。
  - 後台每 2 秒打一次招呼。
  - 遊戲聽到招呼後每秒送一份現況；5 秒沒聽到就停。
  - 沒開後台時，遊戲什麼都不送。
- 遊戲端：`App.tsx` 的 `adminSnap` 組現況，`startAdminLink` 收指令：
  - 速度：`setSpeed`。
  - 時間：`setClock`，只改時間，不改是第幾天。
- 檢查：`tests/e2e/_admin184.mjs`（在 git 外）：
  1. 先只開後台；再開遊戲、開店、讓客人進來。
  2. 後台連上後逐頁讀內容。
  3. 按兩倍速、跳到 16:30，到遊戲那邊確認真的變了。

## 守則

- 後台只改正在跑的這一局，不寫任何存檔。
- 不碰瀏覽器存的飲料庫存（`jgs-drinks-1`，固定規則 1）。
- 以後要加「清掉某些存檔」的功能，也不能包括它。

## 之後可以加的（第二期，等店主說）

1. **調參數**：菜價、成本比例、來客的人潮與耐心，即時套到這一局，測平衡用。
2. **觸發事件**：叫一位客人進來、叫外場去洗碗、讓炭火變弱，重現問題用。
3. **圖表**：每天的營收、盈虧、評價畫成折線。
4. **多個遊戲分頁**：同時開好幾局時，可以選要看哪一局。
5. **匯出這一局**：把現況存成檔案，回報問題時附上。
